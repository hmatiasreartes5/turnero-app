# Spec Funcional: [Nombre del Feature/Módulo]

## 1. Visión del Producto
- **Problema**: qué dolor resuelve.
- **Solución**: qué hace la app.
- **Propuesta de valor**: por qué es mejor que las alternativas.

## 2. Público Objetivo
Persona(s) con contexto de uso, perfil, volumen, tecnología, dolor actual, motivación.

## 3. Plataformas
Tabla con plataforma, soporte (principal/secundario) y enfoque técnico.

## 4. User Stories
Formato: "Como [rol] quiero [acción] para [beneficio]".
Priorizadas con MoSCoW: Must / Should / Could / Won't.
Agrupadas por módulo o área funcional.

## 5. Pantallas y Flujos de Navegación
- Mapa de navegación (diagrama).
- Descripción de cada pantalla: qué ve el usuario, qué acciones tiene, estado vacío.

## 6. Reglas de Negocio
Numeradas (RN-XX). Explícitas, sin ambigüedad.

## 7. Diagramas de Estado
Para entidades con lifecycle (ej: turno, pedido, ticket). Transiciones permitidas y prohibidas.

## 8. Notificaciones
Tabla: qué notificación, cuándo se dispara, qué mensaje muestra.

## 9. Edge Cases
Tabla: caso → comportamiento esperado.

## 10. Priorización MoSCoW
- **Must Have** (MVP)
- **Should Have**
- **Could Have**
- **Won't Have** (fuera de scope)

## 11. Puntos Abiertos
Decisiones pendientes que deben resolverse antes o durante el desarrollo.
